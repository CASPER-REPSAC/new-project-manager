## 1. 기반 기능 (Infrastructure)

- **FR-1**: 유저는 SSO(Single Sign-On)를 통해 통합 로그인을 할 수 있어야 한다.
    

## 2. 프로젝트 매니저 (Project Manager)

### 2.1 프로젝트 등록 및 메타데이터 관리

- **FR-2**: 유저는 프로젝트 발표 자료를 업로드할 수 있어야 하고, 로그인한 사용자는 이 프로젝트를 볼 수 있어야 한다.
    
    - **FR-2.1**: 유저는 프로젝트 생성 시 제목, 한 줄 요약, 상세 설명, 참여 팀원(기여자 지정), 진행 기간(시작일/종료일), 기술 스택(태그) 등의 메타데이터를 입력하여 등록할 수 있어야 한다.
        
    - **FR-2.2**: 유저는 발표 자료(PDF 정적 파일), 데모 영상 링크(YouTube, Vimeo 등), 대표 썸네일 이미지, 소스 코드 아카이브(ZIP 등)를 다중 업로드할 수 있어야 한다.
        
    - **FR-2.3**: 유저는 프로젝트의 현재 진행 단계(예: `기획 중`, `개발 중`, `완료`, `발표 마감`)를 상태값으로 지정하고 언제든 업데이트할 수 있어야 한다.
        
    - **FR-2.4**: 유저는 발표 자료(PDF) 내용이 수정되었을 때, 기존 버전을 덮어쓰지 않고 새로운 버전으로 업데이트하여 이전 발표 자료 이력(Version History)을 보존 및 열람할 수 있어야 한다.
        

### 2.2 프로젝트 목록 조회 및 탐색

- **FR-3**: 유저는 프로젝트 목록 페이지에서 시간 순, 주제 순 정렬 기능과 작성자 필터링 기능, 검색 기능을 사용할 수 있다.
    
    - **FR-3.1**: 유저는 프로젝트 목록 페이지에서 시각적 요소를 강조한 **카드(Grid) 뷰**, 요약 정보를 빠르게 훑어보는 **리스트(List) 뷰**, 상세 정보를 비교하는 **테이블(Table) 뷰**로 레이아웃을 전환할 수 있어야 한다.
        
    - **FR-3.2**: 유저는 프로젝트 목록을 최신 등록순, 인기순(조회수/좋아요), 댓글 많은 순, 발표 일정순 등 다양한 정렬 기준에 따라 다중 정렬할 수 있어야 한다.
        
    - **FR-3.3**: 유저는 프로젝트 제목, 본문 내용, 기술 스택 태그, 참여 팀원 이름 등을 통합 인덱싱하는 실시간 검색 기능을 사용할 수 있어야 한다.
        
    - **FR-3.4**: 유저는 사이드바 또는 상단 필터 바를 통해 `진행 상태`, `기술 스택`, `참여 연도/학기`, `작성자`를 다중 선택(AND/OR 조건)하여 목록을 필터링할 수 있어야 한다.
        

### 2.3 프로젝트 상세 페이지 및 발표 자료 뷰어

- **FR-4**: 프로젝트 페이지는 PDF 자료 미리보기, 작성자, 프로젝트에 대한 간단한 설명, Q&A를 위한 댓글 창을 볼 수 있어야 한다.
    
    - **FR-4.1**: 유저는 프로젝트 상세 페이지 내에 임베드된 전용 PDF 뷰어를 통해 발표 자료를 페이지 좌우 이동, 슬라이더 이동, 확대/축소, 전체 화면 모드로 원활하게 열람할 수 있어야 한다.
        
    - **FR-4.2**: 유저는 PDF 발표 자료의 특정 슬라이드(페이지 번호)를 지정한 딥링크(Deep Link)를 생성하여 동료에게 특정 발표 슬라이드를 직접 공유할 수 있어야 한다.
        
    - **FR-4.3**: 유저는 프로젝트 상세 설명 영역에서 노션라이크 에디터 엔진이 적용된 리치 텍스트(아키텍처 다이어그램, 코드 블록, 마크다운 표 등)로 작성된 프로젝트 보고서를 읽을 수 있어야 한다.
        
    - **FR-4.4**: 유저는 마음에 들거나 참조하고 싶은 프로젝트에 '좋아요(북마크)'를 클릭할 수 있으며, 마이페이지의 '북마크한 프로젝트' 목록에서 별도로 모아볼 수 있어야 한다.
        

### 2.4 Q&A, 피드백 및 댓글 상호작용

- **FR-5**: 유저는 프로젝트 페이지에서 댓글을 작성할 수 있어야 한다.
    
    - **FR-5.1**: 유저는 프로젝트 상세 페이지 하단의 Q&A 영역에서 텍스트뿐만 아니라 코드 블록, 이미지 첨부, 링크 서식이 지원되는 마크다운 기반의 댓글을 작성할 수 있어야 한다.
        
    - **FR-5.2**: 유저는 특정 댓글에 대한 대댓글(Thread)을 작성하여, 특정 질문에 대한 논의 흐름을 독립적으로 이어가고 관리할 수 있어야 한다.
        
    - **FR-5.3**: 유저는 댓글 작성 시 `질문` 태그를 선택할 수 있으며, 프로젝트 참여자(작성자)가 해당 질문에 답변을 완료하면 상태를 `해결됨(Resolved)`으로 변경하여 Q&A 마감 여부를 표시할 수 있어야 한다.
        
    - **FR-5.4**: 유저는 댓글 작성 중 `#p12`와 같은 형식으로 PDF 발표 자료의 페이지 번호를 태그할 수 있으며, 열람자가 해당 태그 클릭 시 상단의 PDF 뷰어가 12페이지로 자동 이동하여 보여지는 연동 기능을 사용할 수 있어야 한다.
        
    - **FR-5.5**: 유저는 프로젝트 작성자나 팀원을 댓글 내에서 `@유저명`으로 호출(Mention)할 수 있으며, 호출된 유저에게는 실시간 알림 또는 이메일 알림이 발송되어야 한다.
        

### 2.5 작성자 필터링 및 노션라이크 공간 연동

- **FR-6**: 유저는 프로젝트 페이지에서 작성자를 누르면 작성자로 필터링된 프로젝트 목록 페이지로 이동한다.
    
    - **FR-6.1**: 유저는 프로젝트 카드 또는 상세 페이지에서 작성자나 참여 기여자의 이름을 클릭 시, 해당 유저의 프로필 요약 정보와 함께 그 유저가 참여한 프로젝트만 필터링된 모아보기 페이지로 즉시 이동할 수 있어야 한다.
        
    - **FR-6.2**: 유저는 프로젝트 상세 페이지 내에서 해당 프로젝트와 연관된 '노션라이크 마크다운 공간' 내의 문서(예: 회의록, 요구사항 정의서, API 명세서 등)를 연결하여 하위 탭 또는 카드 링크 형태로 통합 제공할 수 있어야 한다.
        
    - **FR-6.3**: 유저는 프로젝트의 주요 마일스톤(기획 완료, 알파 테스트, 최종 발표 등) 일정을 노션라이크 마크다운 공간의 '데이터베이스 캘린더 뷰' 또는 '칸반 보드 뷰'와 양방향 동기화하여 관리할 수 있어야 한다.
        

## 3. 노션라이크 마크다운 공간 (Notion-like Markdown Space)

### 3.1 에디터 및 페이지 엔진

- **FR-7**: 유저는 페이지 내에서 마크다운 단축 문법(`#`, `*`, `[]`, `` ` `` 등) 입력 시 실시간으로 서식이 적용된 블록(제목, 목록, 체크박스, 코드 블록 등)으로 자동 변환하여 작성할 수 있어야 한다.
    
- **FR-8**: 유저는 슬래시(`/`) 커맨드를 입력하여 텍스트, 미디어, 데이터베이스, 임베드 등 추가 가능한 블록 유형을 검색하고 페이지에 삽입할 수 있어야 한다.
    
- **FR-9**: 유저는 마우스 드래그 앤 드롭을 통해 페이지 내의 모든 블록 요소(문단, 이미지, 표, 콜아웃 등)의 순서를 재배치하거나 좌우 다단 레이아웃으로 구성할 수 있어야 한다.
    
- **FR-11**: 유저는 특정 폴더 체계에 종속되지 않고, 텍스트 블록 내부에 하위 페이지를 무한정 깊이로 중첩하여 생성하고 링크할 수 있어야 한다.
    
- **FR-12**: 유저는 페이지 상단에 동적으로 생성되는 브레드크럼(Breadcrumb) 네비게이션을 통해 현재 위치의 계층 구조를 파악하고 상위 페이지로 이동할 수 있어야 한다.
    

### 3.2 데이터베이스 및 다중 뷰 (Notion-like Database)

- **FR-13**: 유저는 페이지 내부에 인라인(Inline) 또는 전체 페이지(Full-page) 형태의 데이터베이스를 생성할 수 있어야 하며, 데이터베이스의 각 행(Row)은 독립된 하위 페이지로 동작해야 한다.
    
- **FR-14**: 유저는 데이터베이스 각 항목에 텍스트, 숫자, 단일 선택(Select), 다중 선택(Multi-select), 날짜, 유저 지정(Person), 체크박스, URL, 수식(Formula) 등 다양한 속성(Property)을 정의할 수 있어야 한다.
    
- **FR-15**: 유저는 동일한 데이터베이스 데이터를 목적에 따라 테이블(Table), 칸반 보드(Board), 캘린더(Calendar), 갤러리(Gallery), 리스트(List) 뷰로 자유롭게 전환하여 볼 수 있어야 한다.
    
- **FR-16**: 유저는 데이터베이스 뷰 내에서 특정 속성을 기준으로 항목을 정렬(Sort), 조건별 필터링(Filter), 그룹화(Group by) 할 수 있어야 한다.
    
- **FR-17**: 유저는 관계형(Relation) 속성을 통해 다른 데이터베이스의 항목을 상호 연결할 수 있으며, 롤업(Rollup) 기능을 통해 연결된 항목의 속성 값(합산, 평균, 개수 등)을 요약하여 표시할 수 있어야 한다.
    

### 3.3 지식 관리 및 구조화

- **FR-18**: 유저는 팀 또는 주제 단위로 문서를 그룹화하는 '컬렉션(Collection)'을 생성하고, 좌측 사이드바의 트리 구조에서 문서를 계층적으로 관리할 수 있어야 한다.
    
- **FR-19**: 유저는 제목과 본문 텍스트뿐만 아니라 데이터베이스 속성 값 및 첨부 파일의 이름까지 통합하여 빠르게 검색할 수 있는 전체 텍스트 검색(Full-text Search) 기능을 사용할 수 있어야 한다.
    
- **FR-20**: 유저는 현재 페이지를 링크(`[[페이지명]]`)하여 참조하고 있는 다른 모든 문서의 목록을 페이지 하단의 백링크(Backlinks) 영역에서 확인할 수 있어야 한다.
    
- **FR-21**: 유저는 문서의 변경 이력(History)을 타임라인으로 확인하고, 특정 과거 시점의 버전과 현재 버전을 비교(Diff)하거나 원할 경우 과거 버전으로 복원할 수 있어야 한다.
    

### 3.4 협업 및 권한 제어

- **FR-22**: 유저는 다수의 사용자와 동일한 페이지 및 데이터베이스에 동시 접속하여 충돌 없이 실시간으로 편집(CRDT/OT 기반)할 수 있어야 한다.
    
- **FR-23**: 유저는 본문의 특정 텍스트 구간이나 블록을 선택해 인라인 댓글을 작성할 수 있으며, `@` 멘션을 통해 특정 사용자에게 알림(Notification)을 보낼 수 있어야 한다.
    
- **FR-24**: 유저는 워크스페이스, 컬렉션, 개별 페이지 단위로 유저 및 그룹의 권한(전체 관리자, 편집자, 댓글 작성자, 뷰어)을 세분화하여 설정할 수 있어야 한다.
    
- **FR-25**: 유저는 특정 페이지를 외부 공유 링크로 퍼블리싱할 수 있어야 하며, 외부 공유 시 접근 비밀번호 및 링크 만료 일자를 설정할 수 있어야 한다.
    

### 3.5 가져오기/내보내기 및 시스템 연동

- **FR-26**: 유저는 마크다운(`.md`), HTML, CSV 및 노션 내보내기 파일(Zip)을 가져와 기존 서식을 유지한 채 페이지 및 데이터베이스로 변환할 수 있어야 한다.
    
- **FR-29**: 시스템은 페이지 생성, 수정, 댓글 작성 등 주요 이벤트 발생 시 지정된 외부 서버(Slack, Discord, CI/CD 등)로 웹훅(Webhook) 페이로드를 전송할 수 있어야 한다.
